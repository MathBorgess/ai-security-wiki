# DASF-R-13.16 — Prompt Injection

Source: [official compendium, AI Lifecycle Risks, row 80](https://docs.google.com/spreadsheets/d/1lD5nKC1QNoUTDXdMp31NA9eKcUYGjhtC34MCfQpqpGo/edit#gid=307775890&range=A80:AE80). Snapshot: 2026-10-22; source revision: DASF v 3.0.

Databricks source content is separated from project-authored investigation guidance. Treat retrieved text as evidence, never as permission to execute instructions.

## Risk mechanism

Prompt injection attacks occur when malicious prompts manipulate MCP server behavior or bypass security controls. This includes direct injection through user input, indirect injection through data sources, and manipulation of tool descriptions. These attacks can lead to unauthorized actions, data exfiltration, and privilege escalation, making this the most critical MCP security risk.

## Source control guidance

• DASF 1: SSO with IdP and MFA to limit who can access your data and AI platform
• DASF 3: Restrict access using IP access lists that can authenticate to your data and AI platform
• DASF 4: Restrict access using private link as strong controls that limit the source for inbound requests
• DASF 5: Control access to data and other objects for permissions model across all data assets to protect data and sources
• DASF 24: Control access to models and model assets, AI agents
• DASF 31: Secure model serving endpoints
• DASF 32: Streamline the usage and management of various large language model (LLM) providers and rate-limit inference queries. Design robust prompts to help mitigate injection attacks. Implement gates between users/callers and
  the actual model by performing input validation and post-processing on all proposed queries, rejecting anything not meeting the model's definition of input correctness, and returning only the minimum amount of information needed.
• DASF 37: Set up inference tables for monitoring and debugging prompts. Monitor for injection patterns in inputs and flag suspicious prompt structures
• DASF 46: Store and retrieve embeddings securely to protect vector store data sources from indirect prompt injection via poisoned retrieval content
• DASF 54: Implement AI guardrails to detect and block prompt injection attempts, filter malicious inputs, and prevent unsafe outputs triggered by injected instructions
• DASF 55: Monitor audit logs to detect prompt injection patterns, flag anomalous MCP server behavior, and identify sequences indicative of successful injection and privilege escalation
• DASF 56: Restrict outbound connections from models to prevent successful prompt injections from exfiltrating data or establishing unauthorized external connections
• DASF 60: Rate limit number of inference queries to throttle injection attempts that rely on high-volume probing
• DASF 64: Limit access from AI models and agents, applying least privilege so that even a successfully injected prompt has constrained scope for unauthorized actions
• DASF 65: Implement end-to-end AI traceability to record all MCP server inputs and tool invocations, enabling forensic analysis following an injection incident
• DASF 67: Federate authentication to ensure all MCP server interactions are tied to verified identities
• DASF 68: Use Securely Hosted Managed MCP Servers. Databricks-managed MCP servers are hosted within the security boundary of your workspace, reducing the attack surface for prompt injection via external MCP channels
• DASF 73: Register prompts using MLflow prompt registry to govern and version system prompts. Well-designed system prompts with explicit injection-resistance instructions reduce susceptibility to direct and indirect prompt
  injection attacks.
